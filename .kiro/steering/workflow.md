# プロジェクトの進め方 / イテレーション方針

このファイルは chara-collection（お友達図鑑 / キャラ図鑑）プロジェクトの開発の進め方と今後の方針をまとめたもの。新規チャットでも必ず参照する。関連する詳細は次を参照する。

- 仕様一式: `.kiro/specs/chara-collection/`（requirements.md / design.md / tasks.md）
- デプロイ/ホスティング: `.kiro/steering/deployment.md`
- 改善案の精査・ロードマップ全文: `improvement-proposals.md`

## プロダクト概要

- カップルが二人だけの内輪ノリで楽しむ、iPhone のホーム画面に追加して使う PWA。お気に入りキャラ（アニメ・有名人・ポケモン等）を写真付きで登録し、図鑑として眺める。加えて「今日の一枚ガチャ」「ランキング対戦（自動判定トーナメント）」で遊ぶ。
- 公開名は「お友達図鑑」。公開 URL は https://friend-app-psi.vercel.app/。

## 技術スタック / アーキテクチャ

- React + TypeScript + Vite。PWA 化は vite-plugin-pwa（Manifest + Service Worker）。
- 永続化は端末内 IndexedDB（idb ラッパ）。写真は ArrayBuffer(バイト列)+MIME（PhotoData）として保存する（iOS WebKit の Blob 保存バグ回避）。外部サーバーへの送信・同期は一切しない（要件3.8 / 完全オフライン・端末内完結）。
- レイヤー分離: UI（React components）/ hooks（View-State）/ domain（純粋 TS）/ persistence（IndexedDB）/ PWA 基盤。意思決定ロジックは domain の純粋関数へ寄せ、テスト容易性を確保する。
- 開発は Windows で完結（macOS/Xcode 不要）。

## 開発の進め方（守るべき手順）

1. spec 駆動で進める。新しいまとまった機能は、まず `.kiro/specs/chara-collection/` の requirements → design → tasks を更新してから実装する。既存 spec への破壊的でない拡張として追記していく。
2. 実装は tasks.md のタスク単位で進め、完了したら該当タスクのチェックボックスを更新する。
3. ドメインロジックは純粋関数として切り出し、fast-check による Property-Based Testing（最低 numRuns: 100、`// Feature: chara-collection, Property {n}` タグ）で検証する。UI 分岐・エッジは Vitest + React Testing Library のユニットテストで補う。`*` 付きサブタスクは任意テストで、急ぐ場合はスキップ可。
4. 各イテレーション末尾のチェックポイントで、Windows 上で `npm run build`（= `tsc -b && vite build`、型チェック込み）と `npm run test`（= `vitest run`）がグリーンであることを確認する。
5. 実装が一段落したら（イテレーション完了時など）、コミットして main へ push し、Vercel の自動デプロイまで行う。ユーザーは毎回デプロイまでを期待している。main へ push すると Vercel が自動でビルド・デプロイする（型エラーがあると失敗する）。デプロイ関連の注意点は deployment.md に従う（特に package.json は BOM なし UTF-8 で保存）。

## 確定済みの意思決定

- E-3 登録項目追加は「出会った日」＋「イメージカラー」の2項目のみ（イテレーション6で実装済み）。
- E-4 今日の一言は「案B: その日固定」。
- E-5 相関図はオフラインのルールベース自動生成（外部 AI/送信なし）。
- A-4 の効果音は不採用。エクスポート/検索/圧縮 等は当面スコープ外。

## 不変の制約（変更時は要件から見直す）

- 外部サーバーへデータ・写真を送信しない（要件3.8）。オフライン・端末内完結が前提。相関図の「AI っぽい自動生成」もオフラインのルールベースで実現する。
- パステル基調・角丸・横スクロールなし・最小 44×44 CSS px タッチ領域・rem 追従（要件7）。大人かわいいテーマ（要件9）はこれらを満たす上位互換。色/角丸/影/余白/トランジションはトークン（tokens.css）経由で適用する。
- 写真は必須。モデル変更（複数写真化など）を行う場合は旧データの正規化で後方互換を保つ。
